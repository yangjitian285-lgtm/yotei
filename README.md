# よてい — シンプルなスケジュール帳

ふつうのスケジュール帳アプリです。必要なら**恋人や家族など1人とカレンダーを共有**することもできます。
iPhone の「ホーム画面に追加」でアプリのように使えます(PWA)。
**すべて無料**で動く構成です(クレジットカードの登録も不要)。

| 使うもの | 役割 | 料金 |
|---|---|---|
| GitHub Pages | アプリを公開する場所 | 無料 |
| Firebase(Spark プラン) | ログインとデータ保存・共有 | 無料(カード登録なし。上限を超えると止まるだけで課金はされません) |

---

## できること

**ひとりで使う場合**
- 月表示のカレンダー(左右スワイプで月移動)、ホームに今日の予定とこれから1週間の予定
- 複数日の予定、終日の予定、場所・メモ
- 記念日・誕生日の登録とカウントダウン(毎年くり返し対応)
- ダークモード、オフラインでも閲覧可

**共有する場合(任意。設定からいつでもオン/オフ)**
- 相手の予定も同じカレンダーに表示。だれの予定かを色で区別(自分/相手/ふたり)、絞り込みも可
- 予定ごとに公開範囲を選べる
  - 共有 … 相手も見られる・編集できる
  - 予定ありのみ … 相手には時間帯と「予定あり」だけ
  - 非公開 … 相手には表示されない
- 相手が共有の予定を変えると、ホームの「最近の更新」とアイコンの数字バッジでお知らせ
- 記念日は「共有」か「自分のみ」を選べる。「はじまりの日」(交際開始日・結婚記念日など)を入れると◯日目や節目を自動計算(空欄でもOK)

> ⚠️ 完全無料の構成のため、**アプリを閉じている間のプッシュ通知はありません**(サーバー側の有料機能が必要になるため)。開いたときに更新がわかるようにしています。

## セキュリティ

- ログインは**メールアドレス+パスワード**(8文字以上・英字と数字)。**メール確認が済むまで何も使えません**
- データは Firestore のセキュリティルール(`firestore.rules`)で保護
  - 非公開の予定はあなた専用の場所に保存され、共有相手を含め他人は読めません
  - 共有データは共有している2人以外読めません
  - 「予定ありのみ」の予定は、共有側には中身が空のデータしか置かれません(ルールでも空であることを強制)
  - 共有メンバーは後から変更不可(第三者が割り込めない)
  - 書き込みは項目名・型・文字数までチェック。履歴のなりすまし不可
- 招待コードは**8文字(約1兆通り)・30分で失効・1回きり**。一覧取得は禁止
- 画面に出す文字はすべて無害化(XSS 対策)、Content-Security-Policy を設定
- `firebase-config.js` の値は公開されても大丈夫な種類のものです(守っているのはルール)

## まずはパソコンで試す(デモモード)

`firebase-config.js` が空のままだと、この端末の中だけで動く**デモモード**で起動します。

1. このフォルダでコマンドを実行(Python が入っています)
   ```
   python -m http.server 8765
   ```
2. ブラウザで http://localhost:8765 を開く
3. 「設定」タブの「デモ: 相手が予定を追加したことにする」で、通知の動きも試せます

## 本番の準備(2人で使えるようにする)

所要時間:30分くらい。順番どおりに進めてください。

### 手順1:Firebase プロジェクトを作る

1. https://console.firebase.google.com を開き、Google アカウントでログイン
2. 「プロジェクトを作成」→ 名前は `yotei` など → **Google アナリティクスはオフ**でOK → 作成
3. 左のメニュー「構築」→「**Authentication**」→「始める」
   - 「ログイン方法」タブ →「**メール / パスワード**」→ 1つ目のスイッチをオン → 保存
4. 左のメニュー「構築」→「**Firestore Database**」→「データベースの作成」
   - ロケーション:**asia-northeast1(東京)**
   - 「**本番環境モード**」で開始
5. Firestore の「**ルール**」タブを開き、中身を全部消して、このフォルダの `firestore.rules` の中身を**まるごと貼り付け**→「**公開**」

> 料金プランが「Spark(無料)」になっていることを左下で確認してください。「Blaze」にアップグレードしなければ課金されることはありません。

### 手順2:設定値を `firebase-config.js` に貼る

1. Firebase の画面左上の ⚙️ →「プロジェクトの設定」
2. 下の方「マイアプリ」→ **`</>`(ウェブ)** のアイコン → アプリ名 `yotei` → 登録(Hosting のチェックは不要)
3. 表示される `const firebaseConfig = { ... }` の中の値(apiKey など6つ)を、このフォルダの `firebase-config.js` の同じ場所に貼り付けて保存

### 手順3:GitHub Pages で公開する

1. https://github.com にログイン → 右上「+」→「New repository」
   - 名前:`yotei` / **Public** を選択 → 「Create repository」
   - ※ GitHub の無料プランで Pages を使うには Public が必要です。データは Firebase 側にあり、リポジトリに入るのはアプリのプログラムだけなので Public で問題ありません
2. 作成後の画面の「**uploading an existing file**」をクリック
3. この `yotei` フォルダの**中身すべて**(`icons` フォルダごと)をドラッグ&ドロップ →「Commit changes」
4. リポジトリの「Settings」→ 左の「Pages」
   - Source:「Deploy from a branch」/ Branch:「main」「/(root)」→ Save
5. 1〜2分待つと `https://(あなたのGitHub名).github.io/yotei/` で開けるようになります

### 手順4:Firebase に公開先を登録

1. Firebase →「Authentication」→「設定」タブ →「**承認済みドメイン**」
2. 「ドメインを追加」→ `(あなたのGitHub名).github.io` を追加

### 手順5:iPhone に入れる(共有する場合は相手も)

1. iPhone の **Safari** で公開URLを開く
2. 下の共有ボタン(□に↑)→「**ホーム画面に追加**」→ 追加
3. ホーム画面の「よてい」アイコンから開く
4. 「新規登録」→ 届いた確認メールのリンクを開く →「確認しました」
5. 表示名と色を決める
6. ひとりで使うなら「ひとりで使う」を選んで完了。共有するなら、**どちらか1人**が「招待コードを発行」→ LINE などでコードを送る → もう1人が「招待コードを入力する」に入れる → 共有開始(あとから「設定」→「共有を設定する」でもできます)
7. 通知バッジを使うなら「設定」→「通知をオンにする」

> ホーム画面のアプリと Safari はログイン状態が別です。ホーム画面のアイコンから開いてログインしてください。

## アプリを更新したとき

1. ファイルを直したら GitHub に同じようにアップロード(上書き)
2. `sw.js` の `VERSION = 'yotei-v1'` の数字を上げておくと、iPhone 側にも確実に新しい版が届きます
3. `firestore.rules` を変えたときは Firebase の「ルール」タブにも貼り直して「公開」

## ファイル構成

| ファイル | 内容 |
|---|---|
| `index.html` / `style.css` / `app.js` | 画面と動き |
| `backend-firebase.js` | Firebase とのやりとり |
| `backend-local.js` | デモモード(端末内だけで動く) |
| `firebase-config.js` | Firebase の設定値(手順2で貼る) |
| `firestore.rules` | セキュリティルール(手順1で Firebase に貼る) |
| `sw.js` / `manifest.webmanifest` / `icons/` | ホーム画面アプリ化・オフライン対応 |
